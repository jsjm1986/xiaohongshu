# R08 假设场景重构实施报告

## 结论

F12、F13、F41 已从容易被误读为“用户分布/心理真值”的表达，重构为可修正的写作情景合同。系统仍可按入口和阶段调节信息组织，但不再把项目资料、一次点击或阶段选择解释为某个真实读者已经知道什么、经历过什么或处于何种心理状态。

## 数据与执行变化

- `preContactKnown` 只接受用户明确提供的接触前已知，默认 `[]`。
- `availableEvidence` 只保存模型可使用的项目证据；项目 `verifiedFacts` 不会进入 `preContactKnown`。
- `readerConstraints` 只接受用户提供的读者侧限制；项目硬边界另存为 `availableBoundaries`。
- `readerHistory` 未提供或显式为 `null` 时保存为 `history.status=unknown`；显式 `[]` 表示用户确认“没有已知历史”。
- 审慎、信息疲劳和收束需要改为 `low/medium/high` 情景等级，附未标定区间、`calibrated=false` 和形成依据。区间只用于表达调节，不是心理量表或人群比例。

API 对三个用户字段执行数组类型、去空、去重、数量和单项长度校验。结果页分别展示用户已知、模型证据、假设缺口、读者约束、内容边界、历史状态和未标定假设；旧版 `known` 与 0.x 快照仅以历史兼容警告展示。

## 提示词边界

系统提示和任务提示均明确：

1. `stateSeed` 是可修正写作情景；
2. `availableEvidence` 绝不能改写成“读者原本就知道”；
3. `history.status=unknown` 时不得补写搜索、浏览、消费或项目经历；
4. 定性等级不得写成真实个人心理判断、诊断或人群分布。

旧 UI 的“读者警惕性 44%”实际只映射证据严格度和边界显式度，现已改名为“证据审慎 / 边界显式控制”，不再冒充读者测量。

## 正反例

正确：用户明确输入“读者已看过基础介绍”，系统可把它写入 `preContactKnown`；项目资料中的“适用条件需核验”仍只属于 `availableEvidence/availableBoundaries`。

错误：因为项目知识库写了某项优势，就自动生成“你应该已经了解这个优势”；或因为入口是搜索，就断言读者“已经比较了很多家、现在很疲劳”。这些内容没有用户输入或观测支持，必须保持未知。

## 版本与验证

公式 F12/F13/F41 的方程、执行说明、边界和 canonical fingerprint 已更新；R08 落地版本为默认公式 `1.3.0`、执行策略 `3.2.0`。后续 R10 合并后的当前版本为 `1.4.0/3.3.0`，F12/F13/F41 语义指纹未被改变。Core 覆盖默认未知、用户显式输入、证据隔离、未标定等级和提示词边界；API 覆盖输入清洗与完整生成链；Web 覆盖新旧快照展示与心理百分比去误导。
