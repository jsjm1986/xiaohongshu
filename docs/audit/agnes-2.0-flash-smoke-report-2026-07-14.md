# Agnes 2.0 Flash 隔离生成测试（2026-07-14）

## 总结

`agnes-2.0-flash` 比此前测试的模型更兼容：短请求、项目分析和两种完整生成模式均能完成。但当前仍不建议直接切换为生产默认模型，原因是完整生成耗时 5—12 分钟、请求存在间歇性 `fetch failed`，且 6 个真实候选全部未通过内容校验。

测试凭证只注入当前测试进程，没有写入 `.env`、SQLite、提示词捕获或报告。测试使用生产数据库的隔离克隆，生产库未新增生成记录。

## 接口与流程结果

| 测试 | 结果 | 用时 |
|---|---|---:|
| 兼容接口短 JSON 请求 | HTTP 200，返回合法 JSON | 14.4 秒 |
| 项目全量分析 | 完成：13 个信息缺口、9 个表达策略、13 个选题机会 | 57.5 秒 |
| 简单模式完整生成 | 完成，3 个候选 | 298.7 秒 |
| 设置模式完整生成 | 完成，3 个候选 | 625—707.6 秒 |

项目分析虽然结构合法，但标题和策略主要使用英文；12 个分析缺口和 12 个选题仍为草稿，最终生成使用了隔离测试创建的人工复核缺口/选题。因此“分析成功”还不等于分析资源已经达到中文生产可用标准。

## 稳定性与提示词负载

设置模式独立运行共发生 16 次 HTTP 尝试：9 次成功、7 次 `fetch failed`。9 次成功对应 3 个候选的首次生成与最多 2 次修复；失败请求由重试机制吸收，最终作业完成。

- 首次生成用户提示约 55,600 字符。
- 修复提示增长至约 81,000—86,000 字符。
- 每次允许输出 8,000 tokens。
- 当前单任务将三个候选、严格 JSON、知识库、公式说明和修复上下文叠加，导致延迟和失败概率明显放大。

## 参数与公式是否生效

参数不是摆设，能观察到明确输出差异：

- 简单模式：正文 320、426、320 字；每个候选 4 条评论、3—4 类角色。
- 设置模式：正文 180、180、166 字；每个候选 7 条评论、4—6 类角色。
- 每个候选均记录 75 条参数追踪和 45 条行为指令。

但 `formulaResults` 仍为 0。43 个公式被用于配置、路由、提示词约束和审计，不代表 43 个数学计算器实际执行。所有候选的计划缺口 `closureRate=1`，实际内容 `realizedResolvedRate=0`；校验器正确识别出 `gap_resolution_not_realized`，说明公式规划与最终文案之间仍有断层。

## 生成质量

简单模式和设置模式均为 0/3 合格，每个候选已执行 2 次修复。主要问题包括：

- 事实没有正确映射到证据账本，出现 `visible_fact_not_in_ledger`、`verified_claim_without_evidence` 和 `verified_thread_claim_not_mapped`。
- 评论问题通常长达 50—70 个汉字，不符合“短、自然、单一缺口”的要求。
- 多条回复重复同一结论，并泄漏 `evidence_approved_planning_context`、“本线程”等内部术语。
- 180/320 字硬截断会切断句子；简单模式还有一个候选达到 426 字。
- 评论条数和角色数量增加了，但信息增量不足，读者无法通过不同问题逐步发现新的有效信息。
- 修复阶段出现 `repair_parse_failed`，严格校验问题没有在两轮内消除。

## 建议

Agnes 可作为下一轮优化的候选模型，但应先把生成拆成“规划—单候选正文—评论线程—证据对齐—局部修复”，避免把整个历史输出重新塞入 8 万字符修复提示。还应使用句界安全截断、隐藏内部证据标识，并把 `realizedResolvedRate=0` 或全候选无效的作业标为 `needs_review`，而不是普通 `completed`。完成这些改动后，再用相同矩阵复测并决定是否替换生产模型。
