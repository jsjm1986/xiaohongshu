# 生产质量优化审计（2026-07-14）

## 目标

本轮以“生成的完整文案能否直接进入人工发布审核”为最高目标。公式、参数、编排和证据台账只作为生产约束，不允许因追求指标完整而污染正文或阻断整个生成任务。

## 从实际生成发现的问题

- 正文会在字数上限处截断半句。
- 评论区被规划字段覆盖，出现 `$1`、`evidence_*`、“本线程”等内部词。
- 多条评论重复同一答案，问题过长，条件差异未真正落实。
- 修复提示词重复注入完整知识库和候选，体积持续膨胀。
- 任一候选网络失败会使三份候选全部丢失。
- 任务执行完成与内容质量通过没有区分。
- 供应商完整端点会被错误拼接成重复 `/chat/completions` 路径。

## 已实施的生产改进

1. 正文采用句子安全截断，并为明确要求和关键边界预留字数。
2. 保留模型自然问答，只从编排计划绑定角色、缺口和证据；最终可见文本确定后重算线程、追问和根级证据 ID。
3. 评论按不重复决策条件分配，问题按目标字数压缩；回答使用七种结构并要求新增条件、反例或行动。
4. 局部修复仅携带失败通道、相关计划和相关证据，不再重复整库。
5. 三候选改为独立容错：成功候选保留，失败候选生成明确无效的可审查兜底稿。
6. 新增 `passed / needs_review` 质量状态；无合格候选时 UI 明确提示并继续阻止发布导出。
7. API 地址同时接受基础 URL 和完整端点 URL；结构距离不可达时选差异最大的可用方案并记录偏差，不再中断生产。

## 验证结果

- 单元/集成测试：核心 133 项、Web 58 项、API 38 项。
- 隔离全流程冒烟：简单模式 3/3 合格；高级短正文/丰富评论模式 3/3 合格。
- 两种模式均未检测到 `$1`、`evidence_*` 或线程审计词泄露。
- Agnes 真实调用已确认端点归一化正确，但供应商连续请求稳定性不足；一次复测 6 次请求仅 1 次成功。该结果不能作为成品质量通过证据，已保留为外部服务风险。

## 当前边界

质量门禁验证结构、证据一致性、信息闭合和明显重复，不等于真实平台表现或人工审美评分。正式发布仍需人工复核医疗、价格、资质、活动和保障等动态信息。下一轮真实模型 A/B 应在供应商稳定后，记录通过率、人工盲评分、修复次数和总耗时。
