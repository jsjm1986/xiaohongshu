# 极简创作 · 信息密度与额度可见 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让极简创作在"选题"与"产出"两区把后端已经算出、但前端丢掉的判断依据显示出来——选题卡从"只有标题"变成"标题 + 推荐理由 + 读者阶段 + 排序分与七项指标",产出卡从"看不出为什么可发布"变成"可发布性有据可查";同时给 SaaS 用户一个额度余量仪表,不再让付费用户在毫无预告的情况下撞上 403。简约不是信息少,是每个数字都有出处、都能解释。

**Architecture:** 前端为主。选题与产出的数据后端已经返回(实测 `GET /api/projects/:id/topic-opportunities` 已带 `angle`/`rationale`/`audienceStage`/`entry`/`rank`/`finalScore` 与七项指标,`quickCandidateFields` 已带 `issueCodes`),因此信息密度部分是纯展示层改动,零后端工作。额度部分需要一个新的只读端点:不能直接放行 `GET /api/settings`——它的 `publicSettings` 会连带吐出 `apiBaseUrl`、`model`、`generationDefaults`,属于租户不该看的基础设施细节。改为新增 `GET /api/settings/quota`,只返回 `{providerMode, monthlyQuota, quotaUsed, remaining}`,并单独加进 SaaS 白名单。

**Tech Stack:** NestJS + better-sqlite3(API)、React + TypeScript + Vite(web)、node:test(前后端单测)、monorepo workspaces(@content-agent/api、@content-agent/web)。

## Global Constraints

- **分数必须带"未校准"标注。** 代码里 `scoreSemantics` 明确是 `ordinal_noncausal_heuristic`,`OpportunityRankComponent` 注释写明"uncalibrated, non-causal ordering aids for human review — never facts or predictions"。UI 显示 `0.658` 这类数字时必须同屏标注未校准/仅供人工排序参考,不得出现"预计效果""预测表现"之类措辞。这是本轮唯一的硬约束:说错了就是对付费用户的虚假承诺。
- **不新增后端计算。** 选题分数、指标、`rank` 一律用接口已返回的值原样显示,不在前端重新加权、重新排序、重新归一化。前端算出来的分数没有审计链。
- **额度端点只读。** 新端点不接受任何写入,不返回密钥相关字段(连 `hasApiKey` 也不返回)。BYOK 模式下 `monthlyQuota`/`quotaUsed` 无意义,`providerMode: 'byok'` 时前端不显示额度仪表。
- **白名单最小化。** 只加 `GET /api/settings/quota` 这一条精确路径(不是 `inScope('/api/settings')`),避免顺带放行 PATCH。`apps/api/src/saas-access.ts` 现有的 `verb === 'GET' && pathname === '...'` 精确匹配就是范本。
- 迁移:本轮**不需要**数据库迁移(当前 `user_version = 12`,额度字段 `monthly_quota`/`quota_used` 已在 `workspace_settings`)。
- job 终态 token 是 `completed`(不是 `succeeded`)、失败 `failed`、进行中 `queued`/`running`。
- 复用现有展示组件:仪表格用 `V2Instrument`/`V2InstrumentCell`(`apps/web/src/components/V2.tsx`),不新建仪表组件。校验文案用 `firstValidationIssueLabel`(`apps/web/src/lib/validation-labels.ts`),不硬编码 code 中文。
- **勾选框/单选框样式已在全局归位**(`styles.css` 的 `input[type="checkbox"]` 规则):新增卡片里的裸 checkbox 不要再各自打 `width` 补丁,也不要移除那条全局规则,否则选题卡标题会重新被挤成 0 宽。
- 新增纯函数一律进 `apps/web/src/lib/`,组件只做渲染,便于 node:test 直接测(组件本身无 DOM 测试环境)。
- 测试:`npm run test -w @content-agent/web`、`npm run test -w @content-agent/api`,类型检查 `npm run typecheck -w @content-agent/web` / `-w @content-agent/api`。**新测试文件必须加进对应 package.json 的 `test` 脚本文件列表,否则不会被跑到。**
- API 测试基线有 4 个既有失败(`viewer can read but cannot write projects`、`read-only API keys are workspace-scoped`、`formula registry...`、`planning CRUD...`),已验证在 HEAD 上同样失败。判断回归看"是否新增失败",不是看是否全绿。
- 提交粒度:每个 Task 末尾 commit,message 用 `feat(web,quick): …` / `feat(api,quick): …` / `test(...)` 风格,中文描述。
