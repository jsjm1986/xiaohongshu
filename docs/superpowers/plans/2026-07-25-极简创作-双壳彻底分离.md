# 极简创作:双壳彻底分离

## 现状实测(不是推测,是用真 SaaS 账号跑出来的)

建了一个真的 `userKind: 'saas'` 用户(`saas-probe`,ContentEditor 成员)登录,结果:

```
URL after login: /settings          ← mustChangePassword 强制跳转
hasQuickShell:   false              ← 根本没进极简创作壳
hasExpertSidebar: true
sidebarLinks: 概览 / 内容生成 / 极简创作 / 项目管理 / 知识库 /
              公式版本 / 研究与证据 / 生成历史 / 模型与设置
```

**付费客户第一眼看到的是专家版工作台的整条左侧栏,9 个入口全部可见、可点。** 顶部还有项目切换器、"轻量运行 SQLite / CORE v1.6.0 · POLICY 3.6.0 / 无向量服务"这类内部技术状态。

点进去会怎样:`ProtectedRoute` 把 SaaS 用户弹回 `/quick`,所以数据没漏。但这是**弹回**,不是**不存在**——用户看到 9 个入口、点了 8 个都被踢走。对一个按账号收费的产品,这不是"渐进推进的中间态",这是明确的产品缺陷。

后端是干净的:`SessionAuthGuard` 里 `isSaasApiAllowed` 白名单命中外一律 403(`SAAS_RESTRICTED`),实测 SaaS 会话读 `/api/settings` 就是 403。**所以本轮完全不动权限面,只改前端归属。**

另外查出一个更要紧的问题:

**`/register`「申请开通」审批通过后建出来的用户是 `research`,不是 `saas`。** `registration.service.ts:101` 走 `provisionUserWithWorkspace`,而那个 INSERT 不写 `user_kind`,落到列默认值 `'research'`。也就是说——**从自助注册这条路进来的付费客户,拿到的是完整专家版权限**,前端不拦、后端也不拦(guard 只对 `userKind === 'saas'` 生效)。这比界面问题严重得多。

---

## 一、路由按用户类型分叉(核心)

`App.tsx` 现在是「一个 AppShell 装 11 个路由 + 一个 QuickShell 装 1 个」。改成两棵树,**SaaS 用户的路由树里根本没有专家页面**:

```
<Route element={<ProtectedRoute><QuickShell /></ProtectedRoute>}>
  <Route path="quick" element={<QuickChannelPage />} />
  <Route path="quick/account" element={<QuickAccountPage />} />   ← 新增
</Route>
<Route element={<ProtectedRoute expertOnly><AppShell /></ProtectedRoute>}>
  ... 11 个专家路由不变 ...
</Route>
```

- `ProtectedRoute` 增加 `expertOnly`:SaaS 用户命中即 `Navigate to="/quick"`,**在 AppShell 挂载之前**。现在的问题是先渲染 AppShell 再由内部判断弹走,所以侧边栏会闪出来(实测不是闪,是稳定停在那)。
- `saasPageAllowed` 白名单从 `/quick` + `/settings` 改成 `/quick`(含子路径)。`/settings` 移出——SaaS 用户的账户页改到 `/quick/account`。
- `mustChangePassword` 的强制跳转按用户类型分叉:SaaS → `/quick/account`,专家 → `/settings`。这是本轮最关键的一处:**当前所有 SaaS 用户首次登录都必然落进专家壳**,就因为这个跳转硬编码了 `/settings`。
- `path="*"` 兜底也要分叉:SaaS → `/quick`,专家 → `/`。现在统一去 `/`,SaaS 用户又要被弹一次。

## 二、极简版账户页 `QuickAccountPage`

新建 `apps/web/src/pages/QuickAccountPage.tsx`,渲染在 QuickShell 里,只含 SaaS 用户真正能用的三块:

1. **账号信息** — 用户名、工作区、角色。文案说明账号由管理员开通。
2. **修改密码** — 复用现有 `api.auth.changePassword`(`/api/auth` 整个前缀已对 SaaS 放行)。首次登录时突出提示。
3. **额度余量** — 复用已有的 `quotaCell`(`lib/quota-view.ts`)与 `GET /api/settings/quota`(已在白名单里,精确路径)。工作区 id 从 `GET /api/workspaces`(也在白名单里)取,不依赖"当前选中项目"——账户页可能在没选项目时打开。BYOK/额度为 0 时 `quotaCell` 返回 null,那时不显示这一格(既有行为,不改)。

**不含**:模型来源、API 密钥、BYOK 配置、transport、生成默认值。这些后端对 SaaS 一律 403,放上去只是摆设。

`SettingsPage` 里的 `saas` 分支(`!saas &&` 遮侧栏、`saas ? accountSections : ...`)全部删掉——它不再需要伺候两种用户。这一步同时消掉一处未来的漏点:以后往专家设置页加东西,不必再记得"SaaS 会不会看到"。

## 三、修注册开通的用户类型

`provisionUserWithWorkspace` 增加 `userKind: 'research' | 'saas'` 参数(**必填,不给默认值**),INSERT 里写进去。`registration.service.ts` 传 `'saas'`。

必填而不是默认 `'research'` 是刻意的:这个函数正是漏点所在,让每个调用方都必须明确表态,才不会再有第二次"忘了写就默认成专家"。bootstrap 管理员走的是另一条 INSERT(`auth.service.ts:64`),不受影响。

**已存在的错建用户不自动改**:数据库里现在有 `smoke-research`(research)等账号,哪些是真付费客户、哪些是测试账号只有你知道。我会给出一条查询列出所有 `user_kind='research'` 且非 admin 的账号,由你确认后再改——这是数据操作,不该由我猜。

## 四、QuickShell 补齐

- 顶栏「账户设置」跳 `/quick/account`(现在跳 `/settings`,正好把用户送进专家壳)。
- 「完整版 ↗」链接已经对 SaaS 隐藏(`!isSaasUser(user)`),保持。
- 顶栏补一个额度余量的轻量显示(可选,若 `quotaCell` 返回 null 就不显示)——付费用户在任何页面都该看得见还剩多少。

## 五、测试

`apps/web/test/saas-access.test.ts` 扩写:
- `saasPageAllowed('/settings')` 现在必须是 **false**(行为反转,要锁死)
- `/quick/account` 放行,`/quick-account`、`/quickaccount` 不放行(前缀陷阱)
- 新增 `redirectAfterLogin(user)` / `passwordChangePath(user)` 两个纯函数并逐一锁死:SaaS → `/quick`、`/quick/account`;专家 → `/`、`/settings`。把跳转目标从组件里抽成可测函数,因为这正是当前 bug 的位置。

`apps/api/test/registration.test.ts` 扩写:
- 审批通过后 `users.user_kind` 必须是 `'saas'`(现在是 `'research'`,这条会先失败)
- 该用户登录后 `/api/auth/me` 返回 `userKind: 'saas'`
- 该用户读 `/api/projects` 通、读 `/api/settings` 403 —— 证明 guard 真的对他生效

新增 `apps/api/test/saas-shell-boundary.test.ts`:用真 SaaS 会话逐个打专家 API(`/api/formulas`、`/api/research/*`、`/api/settings`、`/api/admin/users`、`/api/workspaces/:id/members`),断言全部 403 且 code 为 `SAAS_RESTRICTED`。现有 `saas-access.test.ts` 只测纯函数,`saas-quota-access.test.ts` 只测额度那一条;这条把"权限面没被本轮改动放宽"钉住。

## 不做

- **不动后端权限白名单**。它已经正确;本轮任何"顺手放宽"都是风险。
- **不自动迁移已有 research 用户**。给查询、等你确认。
- **不动 `/quick` 内部四区**(总览/知识库/创作/产出),那是前几轮的成果,本轮只动壳与路由。
