# 仿真阅读页设计

日期：2026-07-26
范围：极简创作（基础版）独立阅读页 `/quick/read/:jobId` 的预览区改造

## 问题

阅读页把一篇笔记拆成了表单字段：标题一张带「复制」的卡、正文一张、标签一张、配图说明一张，评论区是一列带徽标的 `<ol>` 问答。用户拿到的是「字段清单」，不是「这篇发出去会长什么样」。

同时页面第一屏被工作信息占满：候选切换条、「这几版差在哪」折叠、红色「须处理才能导出 · 5 项」告警。成品本身要往下滚才看得到。

## 目标

预览区做到尽可能沉浸的小红书笔记仿真——进页面第一眼就是「发出去的样子」。校验、判断依据、导出、改稿这些工作信息保留一个不丢，移到预览下方。

## 不做

- 不加后端字段。全部内容来自现有 `GET /api/generations/:id/reader` 投影。
- 不做真实配图。系统只产出「配图说明」文字，配图位是待拍摄提示。
- 不动完整版（科研版）工作台的详情页。
- 不改生成、校验、导出逻辑。

## 页面结构

```
QuickReaderPage
├─ 顶栏：返回产出 / 标题 / 上一篇·下一篇        （不变）
├─ 候选切换条（极简：小字标签 + 当前高亮）
├─ NoteAlertBar        预览上方一条细横条
├─ NoteCard            仿真笔记（预览区）
│   ├─ 头部：色块头像 + 账号名 + 关注按钮（装饰，不可点）
│   ├─ 配图位 3:4 + 轮播点，框内为 imageBrief 文字
│   ├─ 标题 / 正文 / 蓝色话题标签 / 日期
│   ├─ 互动栏：♡ 点赞  ☆ 收藏  💬 评论 N
│   └─ NoteComments    会话流评论区
└─ ReaderDetail        工作区（删掉原第一段）
    ├─ ValidationVerdict     校验全文
    ├─ 判断依据：缺口台账 / 事实账本 / 来源
    ├─ CommentPlanCard       评论核对（编排信息 + 声明全文）
    ├─ 发布方案
    ├─ 导出 / 按发布顺序复制 / 按同款重新生成
    └─ 按意见修改
```

`NoteCard` 只接 `candidate` 与 `projectName`，不知道校验、导出、改稿的存在。`ReaderDetail` 只管工作台。两者各自可独立理解与测试。

当前候选下标（`index`）原为 `ReaderDetail` 内部状态，现在预览区与工作区都要读它，故提升到 `QuickReaderPage`，以 `activeIndex` + `onPickIndex` 下传两侧。这是本次唯一的状态位置变更。

## 数据映射

全部字段来自 reader 投影，无新增。

| 界面元素 | 数据来源 | 缺失时的行为 |
|---|---|---|
| 头像 | CSS 色块，底色由账号名首字符稳定派生 | — |
| 账号名 | `project.name` | 显示「发布账号」 |
| 关注按钮 | 静态装饰 | — |
| 配图位 | `candidate.imageBrief` | 不渲染配图框，正文直接起 |
| 标题 | `candidate.title` | 不渲染标题行 |
| 正文 | `candidate.body` | 显示「本次未产出正文」 |
| 话题标签 | `candidate.tags` | 不渲染整行 |
| 日期 | `job.completedAt ?? job.createdAt` | 不渲染 |
| 点赞 / 收藏 | 图标 + 文字，**无数字** | — |
| 评论数 | `comments.length` | 为 0 时整个评论区不渲染 |
| 评论昵称 | `comment.displayName` | 回落「读者」 |
| 答复方标记 | `answererLabelFor()`（现有） | `org_answer` 才显示淡「作者」标 |
| 自备首评 | `commentOwnedFirstComment` | 不渲染 |
| 声明全文 | `commentDisclaimer` | 工作区用固定兜底文案 |

评论区身份判定复用 `lib/comment-view.ts` 的 `commentSectionView` / `answererLabelFor`，不新写逻辑。该模块已处理关键陷阱：`reader_exchange` / `organic_reaction` 的 `answer` 是模拟读者接话，不能套机构身份标签。

## 真实性口径

沉浸度优先，但三条不让：

1. **点赞/收藏不给数字。** 图标照排以保证版式完整，数字不写。系统没有平台数据，编造的「129 赞」一旦出现在界面上就会被截图当作业绩证据——与 `CLAUDE.md`「研究图表不是平台表现数据」同一条红线。图标不构成断言，数字构成。
2. **「非真实用户发言」必须可达。** 评论区标题行写「共 N 条评论」+ 一个 ⓘ，悬停/点击展开「情景演练参考，非真实用户发言」。不常驻文字、不折叠成需要翻找的层级。完全删除不可接受：界面会无声断言这些是真实留言，而方法论明确禁止假冒消费者或伪造第三方口碑。
3. **答复身份保留。** `org_answer` 线程的答复显示淡「作者」标。真实小红书页面上作者回复也有此标记，不损沉浸，同时是「答复只能由可追责身份发布」的界面落点。

内部编排字段（`boundary`、`nextStep`、承担缺口、线程功能、读者阶段）一律不进预览区——那是写给运营核对的计划字段，摆在仿真笔记里既破坏沉浸也会把内部指令当文案展示。它们移入工作区的 `CommentPlanCard`。

## 校验告警的位置

`NoteAlertBar` 是预览上方一条细横条，不是卡片：

- 有阻断项：`⚠ N 项需核对才能导出` + 「看详情」锚点跳到下方 `ValidationVerdict`
- 仅建议项：淡色一行 `N 项建议核对`
- 全部通过：`✓ 可直接发布`

实测该项目 21 篇产出里 11 篇为「需人工核对」，这不是罕见路径，所以告警不能只靠禁用导出按钮来表达。但它也不该抢占第一屏——细条是二者的折中。

## 边界与错误处理

- 正文为空 → 「本次未产出正文」，不渲染空气泡
- 无评论 → 整个评论区不渲染，不显示「共 0 条」
- `imageBrief` 缺失 → 不画配图框
- 排队中 / 生成中 / 失败的任务 → 走现有 `WaitCard` 与失败块，**不进** `NoteCard`。半成品套上笔记外壳会像已经发布过
- `displayName` 缺失（历史包）→ 回落「读者」
- 候选数为 1 → 不渲染候选切换条
- 窄屏 <560px → 笔记卡撑满宽度，配图位维持 3:4

## 测试

纯函数层用 `node:test`，新测试文件必须注册进 `apps/web/package.json` 的 `test` 脚本文件列表。

`test/note-view.test.ts`：

- 头像取色对同一账号名稳定、不同名分散
- 日期：`completedAt` 优先、仅 `createdAt`、两者皆缺
- `noteAlertSummary`：阻断项、仅建议项、全部通过三种分类

`test/comment-view.test.ts`（现有）继续覆盖身份判定，`NoteComments` 复用同一套视图函数，不新增重复断言。

组件渲染不写单元测试（项目现无 DOM 测试设施），改由浏览器实测覆盖：四种状态（完成/排队/失败/无评论）各看一眼，窄屏 560px 一眼。

## 已知不可验证项

真实生成链路当前跑不通：三个模型中继均返回 401（缺密钥）。因此本次改造的浏览器实测使用数据库中已有的历史产出，新生成的笔记落地效果无法当场验证。
