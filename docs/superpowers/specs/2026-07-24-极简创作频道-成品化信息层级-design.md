# 极简创作频道(/quick)成品化 — 信息层级重组设计

日期:2026-07-24
分支起点:origin/main(`f6e4186`,含上一轮交互优化 PR #20)
范围:**仅 UI 组织与交互体验**。不改后端契约、不改生成/分析/合规等底层能力(均已成熟)。

## 背景与问题

上一轮(PR #20)完成了视觉对齐 v2 + 交互引导(序号导航、引导条、V2Instrument 状态卡、选中即传)。那一轮在"加";这一轮在"减"。

用户反馈:当前 /quick 仍显"捡漏"、不够成品,冗余的信息显示太多,希望"功能完整但只显示必要的选择和填写"。

经全面盘点五个标签页,**冗余的本质不是某句文案多余,而是"一次性的开荒"和"日常的循环"被摆成了同等地位**:

- **一次性开荒**(每个项目只做一次):建项目 + 传知识 + 分析
- **日常循环**(每天反复跑):选题 → 配置 → 结果

现在 5 个等权平铺标签(`项目&知识 · 选题 · 配置 · 结果 · 历史`)把两种节奏排成一条等长流水线。回头客每次进来都要先经过一整屏"项目设置/上传/分析"才能到真正高频使用的选题。

## 元素使用频率分层(设计依据)

- **① 日常高频**:选已有项目、选题列表、换一批、选预设、生成、结果复制/导出/重生成/换选题、看历史
- **② 一次性设置**:新建项目、上传知识、分析知识库、上传分类/证据类型
- **③ 极少改**:重命名/删除项目、七项高级参数、换一批引导词
- **④ 纯解释文案**(从不操作,只占视线):粉色引导条、未分析空卡、Hero 功能清单副标题、上传分类长说明、选题"已选·进入配置"小字

## 方案:两段式重组(准备区 / 创作区)

保留全部能力,按节奏重新归组,清掉 ④ 层纯文案。

### 主壳导航结构

顶层从"5 个等权平铺标签"改为"三区 + 顶部项目切换器":

```
┌──────────────────────────────────────────┐
│  [当前项目名 ▾]              准备 · 创作 · 历史  │
└──────────────────────────────────────────┘
```

- **准备区**(一次性):知识上传 + 分析
- **创作区**(高频):选题 → 配置 → 结果(区内轻量步骤条串联)
- **历史**:独立入口
- **顶部常驻项目切换器**:切项目是高频动作,提升到顶部,不再埋在准备区

**智能默认落点:**
- 新项目 / 未分析 → 自动进「准备区」
- 已分析(有选题)→ **直接落在「创作区」**,回头客不再穿过开荒屏

**切项目行为:** 停在当前区;在创作区切到已分析项目则刷新选题,切到未分析项目则提示去准备区。

### 准备区(一次性开荒)

单列,聚焦"知识 + 分析"两件事,低频操作下沉:

```
准备区
────────────────
① 知识文件          [＋ 上传 .md/.txt]
   • 产品手册.md   未分类  ✕
   • 案例集.txt    未分类  ✕

② 分析                [分析知识库 ▸]
   分析后 AI 建立内容地图并生成选题
   (分析完变为:✓ 已分析 · 医美 · 16 个选题   [重新分析])
────────────────
   ⌄ 更多设置(重命名 / 删除项目 / 上传分类与证据类型)
```

- **项目选择移走**:已在顶部常驻切换器,准备区不再重复
- **上传极简**:选中即传(已实现),默认"未分类/已知事实"
- **未分析空卡删除**:那张"状态/尚未分析"的 V2Instrument 空卡是纯占位,删。状态直接体现在②按钮区:未分析→主按钮「分析知识库」;分析中→进度条;分析完→顶部一行简洁结果 + 「重新分析」次级按钮
- **低频下沉**:重命名、删除项目、上传分类/证据类型,统一收进底部「更多设置」折叠(证据分类能力保留,只是不在明面平铺)

### 创作区(高频主舞台)

选题 → 配置 → 结果,用区内轻量步骤条串联(替代顶部大标签):

```
创作区
────────────────
 ○ 选题  ——  ○ 配置  ——  ○ 结果
────────────────
[当前步内容]
```

- **选题**:选题卡列表 + 「换一批」。选中即进配置(去掉"已选·进入配置"小字,选中态视觉高亮即可)
- **配置**:**精简预设卡片** + 「生成文案」主按钮。七项高级参数收进「高级设置」折叠(已实现)。生成进度条(已实现)
  - **预设卡片**:预设(真实极简 / 理性比较 / 犹豫补全…)风格差异大,决定文案写法,下拉只显示一个名字导致"选不明白"。改为卡片式:每张显示**名称 + 一句说明 + 默认星标**,选中态高亮。
  - **只保留"选择"动作**:去掉完整 PresetShelf 里的「复制」「内置方法」「设为默认」「更新」等管理操作——管理预设是低频/专家动作,不进 /quick 日常创作路径(按频率分层)。用户在此只需"看懂并选一个"。
- **结果**:候选版本 tab + 复制/导出/重生成/换选题(上轮已改好,仅去冗余小字)
- **去掉粉色引导条**:轻量步骤条已说明"在哪、去哪",不需整条文字重复解释

### 全局文案清理

- **Hero 副标题**「一个页面完成建项目、传资料、选题、配置、生成、看历史」像功能清单,改成一句短定位语或去掉,顶部更清爽
- 清掉所有 ④ 层纯解释文案

## 组件边界与影响

**主壳 `QuickChannelPage.tsx`:**
- 导航从 5 平铺标签 → 三区(准备/创作/历史)+ 顶部项目切换器
- 新增智能落点逻辑(依据项目是否已分析决定初始区)
- 创作区内部用轻量步骤条管理选题/配置/结果的子状态

**准备区**(组合 `ProjectKnowledgeTab` 现有能力,重组布局):
- 移除项目选择(上移到壳)、移除未分析空卡
- 低频操作下沉到「更多设置」折叠

**创作区**(组合 `TopicTab` / `ConfigTab` / `ResultTab`):
- 顶部大标签 → 区内轻量步骤条
- 去引导条、去冗余小字
- `ConfigTab` 预设选择:`<select>` 下拉 → **精简预设卡片**(名称 + 说明 + 默认星标 + 选中高亮,仅"选择"动作,无管理操作)。可参考完整版 `GeneratorPage` 的 `PresetShelf` 视觉,但剥离全部管理功能

**纯状态逻辑** `quick-channel-state.ts`:
- `tabReachable` / `stepStatus` 的语义从"5 标签可达"调整为"三区 + 创作区内三步"的可达/落点判定
- 这是纯函数,可单测覆盖(延续上轮做法)

**不改动:** 所有 `api.*` 调用、生成/分析/导出逻辑、后端契约。

## 测试策略
