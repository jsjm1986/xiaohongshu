# 极简创作频道 交互体验优化 设计文档

## 背景与目标

`/quick`(`QuickChannelPage` + 5 个子标签:项目&知识 / 选题 / 配置 / 结果 / 历史)功能已完整,但视觉粗糙、不像成品,部分交互冗余。本次做一次全面系统的体验优化,让它清晰、方便、简易、不冗余。

**核心判断(已核实):**

- `.v2` 设计系统已通过 `AppShell.tsx:64`(`<div className="app-shell v2">`)套在所有页面外层,`QuickChannelPage` 天然处于 `.v2` 作用域内 —— 复用 v2 token 与组件原语零需 DOM 祖先改动。
- v2 token 定义于 `styles.css` `.v2` 作用域(约 1731 行起):`--v2-canvas/surface/ink/ink-2/muted/muted-2/line/line-dark/brand/brand-strong/brand-soft/ai/ok/warn/error`、`--v2-radius(10)/​-sm(8)/-lg(14)`、`--v2-shadow-sm/md`、`--v2-fs-micro(10)…-h1(28)`、`--v2-mono`。
- v2 原语在 `components/V2.tsx`:`V2Hero`、`V2Instrument({children, columns?})`、`V2InstrumentCell({tone, icon, label, value, unit?, note?, mono?})`、`V2SecLabel`。
- 后台任务进度有现成范式(`IntelligentSimpleFlow.tsx`):`api.intelligence.tasks.list(projectId)` → `AnalysisTask[]`;轮询 `setInterval(refreshLatestTask, 1800)`;展示组件 `TaskProgressRow`。

**约束:**

- 纯前端为主。唯一后端触点在维度 4 的**只读**轮询(复用既有 `api.intelligence.tasks.list`),不改后端契约。
- 不改标签导航的整体架构与页面布局骨架(5 tab、状态提升到 `QuickChannelPage` 的模式保持)。仅改样式 + 复用 v2 原语 + 补交互易用性。
- 语言:界面文案与代码注释保持中文。
- 验证:`typecheck` + `@content-agent/web` 单测保持通过;浏览器端到端因 dev API 原生依赖(`@node-rs/argon2-darwin-arm64`)缺失暂无法登录,如实标注,留本地核验。

## 维度 1 — 视觉基座:`.qc-*` 迁移到 v2 token

**目标:** 消除硬编码颜色/圆角/间距/字号,统一为 v2 设计语言,使面板、卡片、列表看起来是成品。

**改动范围:** 仅 `apps/web/src/styles.css` 内所有 `.qc-*` 规则。纯 CSS,零 TSX 改动。

**映射规则(逐项替换硬编码值):**

| 语义 | 旧(硬编码,示例) | 新(v2 token) |
| --- | --- | --- |
| 常规边框 / 分隔线 | `#ddd` `#e5e5e5` `1px solid #eee` | `var(--v2-line)` |
| 深色分隔 | `#ccc` 类 | `var(--v2-line-dark)` |
| 卡片 / 面板背景 | `#fff` `white` | `var(--v2-surface)` |
| 页面底色 | `#f7f7f7` 类 | `var(--v2-canvas)` |
| 圆角(常规 / 小 / 大) | `6px` `8px` `12px` | `var(--v2-radius)` / `var(--v2-radius-sm)` / `var(--v2-radius-lg)` |
| 正文主色 | `#222` `#1a1a1a` | `var(--v2-ink)` |
| 次要文字 | `#666` `#888` | `var(--v2-muted)` |
| 极弱提示 `.qc-hint` | `#999` + `12px` | `var(--v2-muted-2)` + `var(--v2-fs-small)`(注:极细注解可用 `--v2-fs-micro`) |
| 主色调用(按钮/强调) | `#f05d52` 类 | `var(--v2-brand)` / `var(--v2-brand-strong)` |
| 卡片阴影 | `0 1px 3px rgba(...)` | `var(--v2-shadow-sm)` |

**统一为 v2 卡片语言的元素:** `.qc-panel`、`.qc-analysis-status`、`.qc-file-list li`、选题/结果/历史卡片 —— 一律 `background: var(--v2-surface)`、`border: 1px solid var(--v2-line)`、`border-radius: var(--v2-radius)`(卡片用 `-lg`)、`box-shadow: var(--v2-shadow-sm)`。

**验证:** 视觉回归靠人工;此维度不含逻辑,typecheck 不受影响。任务级验证 = 全站 `.qc-*` 规则内不再出现十六进制颜色字面量(除非 v2 token 本身未覆盖的语义,需在设计评审时列出)。

## 维度 2 — 标签导航:序号 + 状态点 + 下一步引导

**目标:** 让用户随时知道「现在在第几步、下一步做什么、为什么某步不可点」,替代当前只有 hover tooltip 的弱提示。

**现状:** `QuickChannelPage.tsx:98-111` 的 `.qc-tabs` 是下划线式按钮,禁用态仅 `title={TAB_HINT[tab]}`(hover 可见)。

**改动:**

1. **序号 pill** — 每个标签前置序号 `①②③④⑤`(CSS 计数或直接文案),呼应 `V2Hero index="Q"` 的编号语言。pill 用 `border-radius: var(--v2-radius-lg)`。
2. **三态样式:**
   - **当前步(active):** 底色 `var(--v2-brand-soft)`,文字 `var(--v2-brand)`。
   - **已完成步:** 标签尾部一个 `var(--v2-ok)` 小圆点(`.qc-tab-done`),文字 `var(--v2-ink)`。「已完成」判定见下。
   - **未解锁步(disabled):** 文字 `var(--v2-muted-2)`,`cursor: not-allowed`,保留 `title` 兜底。
3. **下一步引导条** — 面板顶部(`.qc-panel` 之上或 nav 之下)新增一行 `.qc-next-hint`,正向文案提示当前该做什么。文案来自现有 `TAB_HINT` 正向化:
   - project 步:`下一步:分析知识库,生成选题`(仅当已选项目且尚未分析时显示;已分析则提示「已就绪,去选题」)。
   - topic 步:`选择一个选题后进入配置`。
   - config 步:`选择模板,点生成`。
   - result 步:`可复制、重新生成或换个选题`。
   - history 步:不显示引导条。
   - 引导条在当前步没有明确「下一步」时(如 result 已是产出)可省略或转为轻提示。

**「已完成」判定(纯前端,复用已有 state):**

- project 已完成:`Boolean(project)` 且已分析(需从 `ProjectKnowledgeTab` 的 `analyzed` 状态提升,或在 `QuickChannelPage` 用 `opportunities.length > 0` 近似 —— 采用 `opportunities.length > 0` 作为「已产出选题」的信号,避免新增跨组件状态)。
- topic 已完成:`Boolean(opportunityId)`。
- config 已完成:`results.length > 0`。
- result 已完成:`results.length > 0`。

**改动范围:** `QuickChannelPage.tsx`(`<nav>` 段 + 新增引导条 + 一个 `tabDone` 记录计算)、`styles.css`(`.qc-tabs` 相关 + `.qc-tab-done` + `.qc-next-hint`)。状态数据全部来自已有的 `reachable` + `project`/`opportunities`/`opportunityId`/`results`,不新增数据流。

## 维度 3 — 项目 & 知识页:状态卡 + 一步上传 + 发丝文件行

**目标:** 分析状态更像仪表、上传少一步、文件列表精致。

**改动范围:** `apps/web/src/components/quick/ProjectKnowledgeTab.tsx` + `styles.css`。

**3.1 分析状态卡 → `V2Instrument`**

现状 `.qc-analysis-status`(`ProjectKnowledgeTab.tsx:161-170`)是纯文字卡。改为 `V2Instrument`:

- **已分析**(`analyzed === true`)时,渲染 `V2Instrument` 含三个 `V2InstrumentCell`:
  - `tone="brand"` label「实体」value `{intel.entity || '已分析'}`
  - `tone="ai"` label「行业」value `{intel.industry || '内容地图已建立'}`
  - `tone="ok"` label「选题」value `{topicCount}` unit「个」
- **未分析**时,渲染单个引导 cell(或保留一行 `.qc-hint`):`尚未分析。上传知识后点「分析知识库」,AI 会建立内容地图并生成选题。`

保留现有 `intel` / `topicCount` state 与加载逻辑(`ProjectKnowledgeTab.tsx:30-43`)不变。

**3.2 一步上传**

现状两步(`:184-194`):选文件(`onChange` 只 `setPending`)→ 再点「上传」按钮(`uploadAll`)。

改为选中即上传:

- `<input type="file">` 的 `onChange` 改为选中后直接 `void uploadAll(files)` —— `uploadAll` 改造为接收文件数组参数(而非闭包读 `pending`),上传后清空 input value 以便重复选同名文件。
- 移除独立「上传」按钮(`:194`)。
- 上传进行中:文件区显示内联「上传中…(N 个)」提示(复用 `busy` 或新增局部 `uploading` 态);失败进 toast(现有 `fail`)。
- 分类 / 证据类型仍留在 `<details className="qc-advanced">` 折叠里(`:187-193`),选中后即时作用于后续上传(用户想改分类先展开设置再选文件)。

`uploadAll` 新签名:`const uploadAll = async (list: File[]) => { … for (const f of list) await api.knowledge.upload(project.id, f, category, kind); … }`。`pending` state 可移除。

**3.3 发丝文件行**

`.qc-file-list li`(`:173-181`)改 v2 发丝线行:`border-bottom: 1px solid var(--v2-line)`、`padding` 用 v2 间距、hover 微底色(`background: var(--v2-brand-soft)` 的极淡变体或 `var(--v2-canvas)`)、删除按钮 ghost 图标(现已是 `variant="ghost"`)。空态 `.qc-hint` 保留。

## 维度 4 — 长耗时反馈:分析 / 生成阶段进度

**目标:** 分析(几十秒)和生成(数秒到数十秒)期间给出明确进度反馈,防止用户误以为卡死或重复触发。复用 `IntelligentSimpleFlow` 的既有范式,**只读轮询,不改后端**。

**改动范围:** 新增 `apps/web/src/components/quick/QuickTaskProgress.tsx`;改 `ProjectKnowledgeTab.tsx`、`ConfigTab.tsx`、`ResultTab.tsx`;`styles.css` 加进度条样式。

**4.1 `QuickTaskProgress` 组件(仿 `TaskProgressRow`)**

```tsx
import { RefreshCw } from 'lucide-react';
import type { AnalysisTask } from '../../types';

export function QuickTaskProgress({ text, task }: { text: string; task?: AnalysisTask | null }) {
  const active = task != null && (task.status === 'running' || task.status === 'queued');
  const failed = task?.status === 'failed';
  return (
    <div className="qc-progress" role="status">
      <RefreshCw size={15} className="spin" />
      <span>{text}</span>
      <small>{failed ? `失败:${task?.error ?? '未知错误'}` : active ? `后台进行中 · 第 ${task.attemptCount} 次尝试` : '处理中…'}</small>
      <i className="qc-progress__track"><b /></i>
    </div>
  );
}
```

`.qc-progress` / `.qc-progress__track` / `.spin` 样式对齐 v2(轨道用 `var(--v2-brand)` 走条,`.spin` 复用全站已有的旋转动画;若 `.spin` 是 `IntelligentSimpleFlow` 局部样式,则在 `styles.css` 补一份等价 keyframes)。

**4.2 分析进度(真实后台任务轮询)**

`ProjectKnowledgeTab`:

- 新增 state `latestTask: AnalysisTask | null`。
- 新增 `refreshTask()`:`api.intelligence.tasks.list(project.id)` → 按 `createdAt` 降序取 `kind === 'project'` 最新一条 → `setLatestTask`。非致命(`.catch` 忽略)。
- `analyze()` 期间(`busy` 或新增 `analyzing` 态)启动 `setInterval(refreshTask, 1800)`,结束清除。
- 在按钮区上方,`analyzing` 时渲染 `<QuickTaskProgress text="三段模型串联:蓝图 → 缺口与策略 → 选题" task={latestTask} />`。
- 任务 `failed` 时,进度组件展示 `error`(已内建),同时保留现有 toast 报错路径。
- 分析期间禁用「分析 / 重新分析 / 去选题」按钮(现有 `loading={busy}` 已覆盖),文案旁加一句「完成前请勿离开或重复触发」。

**4.3 生成进度(确定性阶段文案,不伪造后台任务)**

`ConfigTab` 与 `ResultTab` 的生成走 `autoApproveAndGenerate`(同步 `await`,**不产生 analysis_task**)。因此这里**不轮询**,改用确定性阶段提示,如实呈现:

- 生成期间(`busy`)显示 `<QuickTaskProgress text={stageText} />`(不传 task),`stageText` 用一个本地阶段轮播:`解析选题 → 组织结构 → 生成初稿 → 质检润色`,通过 `setInterval` 每约 2.5s 前进一档(纯展示,不代表真实后端阶段;文案措辞避免暗示精确进度,如「生成中 · 组织结构…」)。
- 生成按钮 `busy` 期间禁用(现有 `loading` 已覆盖),防重复触发。

> 设计取舍:生成路径无后台任务 id 可轮询,若强行伪造「第 N 次尝试」会失真。故分析用真实轮询、生成用诚实的阶段文案,二者共用同一个 `QuickTaskProgress` 视觉外壳,体验一致而不失真。

**4.4 类型引入**

`AnalysisTask` 已定义于 `apps/web/src/types`(`interface AnalysisTask { id; projectId; kind: 'project'|'image'; targetId; status: 'queued'|'running'|'completed'|'failed'; attemptCount; resultId; error; createdAt; updatedAt; completedAt }`)。直接 import,不新增类型。

## 维度 5 — 结果 & 历史:v2 卡片语言

**目标:** 产出与历史统一到 v2 卡片语言,收尾整体成品感。

**改动范围:** `ResultTab.tsx`、`HistoryTab.tsx`、`styles.css`。主要是 CSS + 少量 className,不动数据流。

**5.1 ResultTab**

- 候选卡改 v2 surface 卡:`var(--v2-surface)` + `var(--v2-radius-lg)` + `var(--v2-shadow-sm)` + hairline `var(--v2-line)`。
- 标题 / 正文分区(标题 `var(--v2-fs-h3)` 类 + `var(--v2-ink)`,正文 `var(--v2-muted)` 或 ink-2)。
- 操作按钮(复制 / 重新生成 / 换个选题)统一 v2 按钮语言,主操作 brand、次操作 ghost。
- 保持现有数据流(`QuickResult` 包装、`autoApproveAndGenerate` 重新生成、`goTo('topic')` 换选题)不变。

**5.2 HistoryTab**

- 历史行改 v2 发丝线列表(同维度 3.3 的行样式)。
- 状态徽章用 v2 语义色:完成 `var(--v2-ok)`、进行中/排队 `var(--v2-warn)`、失败 `var(--v2-error)`,小尺寸(`--v2-fs-micro`)。
- 展开的候选卡复用 ResultTab 同款卡片样式(可抽一个共享 `.qc-candidate-card` class 供两处用)。
- **保持已修好的客户端导出不变**(`exportMarkdown` 用 `quickCandidateToMarkdown` 构造 Blob,不走后端 `exportUrl` 以免泄漏审计附录)。复制、无删除等现有行为不变。
