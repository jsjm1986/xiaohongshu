# 极简创作频道 · 设计文档

- 日期:2026-07-24
- 状态:已获用户批准,待写实现计划

## 背景与目标

现有前端是完整的专业创作台:内容生成走 `/generate` 的简单/高级双模式,即便"简单模式"(`IntelligentSimpleFlow`,1177 行)也是一个 4 步引导器,暴露蓝图审批、机会排序启发式、指标编辑、证据选择等专业机制,信息密度高。

产品需要一个**极简的、信息含量很低的快速使用版本**,让新用户以最少的动作走完:新建项目 → 上传知识库 → 分析 → 挑选题 → 选预设 → 生成 → 拿到可直接发布的文案。生成结果**只显示可用文案**(标题、正文、标签、问答话术、可发布首评、图片简报),不显示任何解释说明、审计附录、校验明细。

**硬约束(非入侵式扩展):**

- **不改任何后端业务逻辑。** 全部复用现有 API 接口。
- **不改动现有前端业务逻辑与页面。** 现有 `IntelligentSimpleFlow`、`GeneratorPage`、`GenerationResultPage` 等一律不动。
- 本功能是一个**独立频道**:侧边栏新增一个入口,进入一个独立的极简向导页面(仍在主应用外壳内,复用登录态与项目上下文)。
- 除两处各加一行(路由、导航)外,全部为**新增文件**。

## 已确认的产品决策

1. **选题**:自动分析后,给用户看几个候选选题(**只显示标题**,不显示排序启发式/缺口审计),用户点一个,其余自动。
2. **知识录入**:上传文件(`.md`/`.txt`,单个 ≤2MB,现有接口),可多传。
3. **可用文案范围**:全部可用文案 —— 标题、正文、标签、问答话术评论、可发布首评、图片简报,每项一键复制。
4. **候选呈现**:3 个版本用标签页切换。
5. **快速配置**:仅暴露一个"预设"下拉(复用现有 preset,默认选中 `isDefault`),其余全默认。
6. **入口**:侧边栏新增一个独立导航入口(仍在主框架内,复用登录/项目上下文)。
7. **蓝图审批**:极简版**无条件自动审批全部蓝图模块**,用户看不到蓝图这一层。

## 向导流程与状态机

页面用一个 `step` 状态机线性推进,单页内切换步骤(不跳路由)。

| step | 界面 | 用户动作 | 系统动作 |
|------|------|---------|---------|
| `create` | 项目名称输入框 | 填名 → 下一步 | `useProjects().addProject({ name })` → projectId |
| `upload` | 文件上传区(.md/.txt,≤2MB,可多传) | 选文件 → 分析 | 逐个 `api.knowledge.upload(projectId, file)` |
| `analyzing` | 加载态("正在分析知识库…") | 等待 | `await api.intelligence.analyze(projectId, true)` |
| `pick-topic` | 候选选题卡片(**只显示标题**) | 点一个选题 | 暂存 opportunityId |
| `configure` | 预设下拉(默认选中 `isDefault`) | 选预设 → 生成 | `autoApproveAndGenerate({ projectId, opportunityId, presetId })` |
| `generating` | 加载态("正在生成文案…") | 等待 | 内部:自动审批 → create → 轮询 get 直到 completed |
| `result` | `QuickResult`:3 版标签页 + 可用文案 + 一键复制 | 复制 / 再来一批 / 换个选题 | — |

**关键交互:**

- **顶部进度条**:显示当前走到第几步(纯视觉)。
- **"再来一批"**:回到 `configure` 重新生成(同选题、同项目)。
- **"换个选题"**:回到 `pick-topic`,重新拉一批 `api.opportunities.list`(或 `refresh`)。
- **每步只有一个主动作按钮**,信息量压到最低。

**错误处理(每步):** 任一步失败(建项目/上传/分析/生成),`useToast().push(msg, 'error')` 提示,停在当前步,按钮恢复可点让用户重试 —— 不崩、不跳。

## 自动审批逻辑(`quick-generation.ts` 核心)

后端强制要求:生成前,机会、蓝图模块、机会所依赖的信息缺口/表达策略都必须处于**已审批**状态。现有 `IntelligentSimpleFlow.preview()` 靠一串审批调用凑齐前置状态。此逻辑**照着重写一份精简版**放进新库,不碰原组件。

### 函数签名

```ts
export async function autoApproveAndGenerate(args: {
  projectId: string;
  opportunityId: string;
  presetId?: string;
}): Promise<GenerationJob>
```

### 内部执行序列(全部现有接口)

1. **审批蓝图** —— `api.blueprintModules.list(projectId)`,对未审批的逐个 `api.blueprintModules.approve`(无条件全批)。
2. **审批 intelligence** —— 若 `api.intelligence.get` 状态需审批,调 `api.intelligence.approve`。
3. **定位选中机会 + 其依赖** —— 从 `api.opportunities.list` 找到 opportunityId 对应项,读其引用的 gapIds / strategyIds。
4. **审批依赖** —— 对这些调 `api.informationGaps.approve` / `api.expressionStrategies.approve`。
5. **审批机会本身** —— `api.opportunities.approve(projectId, opportunityId)`。
6. **构建输入** —— `buildSimpleGenerateInput({ projectId, opportunity, settings: resolveSimpleGenerationSettings({ project, preset }), presetId, imageAssetIds: [], lockedGapIds: [], localFieldsEnabled: false, randomizationDimensions: [...默认] })`。
7. **发起生成** —— `const job = await api.generations.create(input)`。
8. **轮询结果** —— 循环 `api.generations.get(job.id)`,间隔 1800ms(沿用现有页面节奏),`status === 'completed'` 返回;`failed` 抛错。

### 设计要点

- 该函数**不含任何 UI** —— 纯逻辑,输入 id、输出 job。UI 层只负责 loading 态与 catch。
- 具体审批调用顺序、依赖字段名、`buildSimpleGenerateInput` 参数,**以 `IntelligentSimpleFlow.preview()`(约 787–863 行)与 `simple-generation.ts` 的真实签名为准**,实现时逐一核对。
- `randomizationDimensions` 默认取值以 `preview()` 现有默认为准。

## 结果呈现(`QuickResult.tsx`)

### 可用文案抽取

```ts
export function quickCandidateFields(candidate: Candidate): {
  title: string;
  body: string;
  tags: string[];
  imageBrief?: string;
  commentOwnedFirstComment?: string;
  comments: Array<{ question: string; answer: string; boundary?: string; nextStep?: string }>;
}
```

只挑可用字段,审计字段一律不取。

### 布局

- 顶部:3 个版本标签页(版本一/二/三,对应 3 个 candidate)。若某版 `validation.valid !== true`,标签旁一个浅色小点提示(不展开原因)。
- 当前版本按卡片纵向排列,每张卡右上角"复制"按钮:

| 卡片 | 内容 | 复制内容 |
|------|------|---------|
| 标题 | `title` | 纯标题文本 |
| 正文 | `body` | 正文全文 |
| 标签 | `tags[]` 渲染成 `#标签` 芯片 | `#a #b #c` 空格拼接 |
| 图片简报 | `imageBrief`(有才显示) | 简报文本 |
| 可发布首评 | `commentOwnedFirstComment`(有才显示) | 首评文本 |
| 问答话术 | `comments[]`,每条 问/答,`boundary`/`nextStep` 附在答下 | 该条问答拼成文本 |

- 底部:两个动作按钮 —— "再来一批"(回 configure)、"换个选题"(回 pick-topic)。
- **"复制全部"**:把当前版本所有可用文案拼成一段 markdown(`quickCandidateToMarkdown`,**不含审计附录**)一次性复制。

**复制交互:** `navigator.clipboard.writeText()` + `toast.push('已复制')`;失败降级不做花活。

### 明确不显示

score、diagnostics、validation 明细、sources/unknowns/conflicts、gapCoverageLedger、各类 audit 字段(personaRole/speakerType/claimStatus/evidenceIds 等)、job 级的 resolvedConfig/configPreview/impactReport/seed/formulaVersion 等 —— 全部不取、不渲染。

## 可发布性处理

- 优先展示 `validation.valid === true` 的候选;标签页顺序保持后端返回顺序。
- 若某版未通过校验,仍展示(标签旁浅色点),**不展开校验细节**,保持极简。

## 错误处理

- 建项目 / 上传 / 分析 / 生成任一步失败 → `toast.push(错误消息, 'error')`,停在当前步可重试。
- 生成轮询到 `failed` → toast 报错,回到 `configure` 可重试。
- 分析后无候选选题 → `EmptyState` 提示"未能从知识库提炼出选题,请补充知识内容后重试",提供返回上传步的入口。

## 测试

- `quick-generation.ts`(纯逻辑,mock api 层):
  - `autoApproveAndGenerate` 按正确顺序调审批 → create → poll;轮询在 `completed` 返回、`failed` 抛错。
  - `quickCandidateFields` 正确抽取可用字段、剔除审计字段。
  - `quickCandidateToMarkdown` 输出不含审计附录分隔符。
- `QuickResult`(组件层,假 job):只渲染可用文案、不渲染审计字段;标签页切换正确;复制调用 clipboard。
- 全流程:前后端 typecheck + web 生产构建;真机浏览器冒烟由用户手动点一遍(本环境无浏览器自动化工具)。

## 明确不做(YAGNI)

- 不做高级参数、指标编辑、证据选择、蓝图人工审阅。
- 不改现有 `/generate` 双模式与结果页。
- 不做知识库文本直接粘贴(仅文件上传)。
- 不做多选题批量生成、不做历史记录页。
- 不新增后端接口、不改后端校验规则。
