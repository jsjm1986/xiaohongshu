# 选题页（第 2 步）全面优化 · 设计文档

- 日期：2026-07-23
- 分支：`feat/topic-diversity`（仓库 `content-agent`）
- 范围：`apps/web/src/styles.css` + `apps/web/src/pages/IntelligentSimpleFlow.tsx`
- 不涉及：后端、数据层、其他页面

## 背景与动机

选题页（内容生成第 2 步，`/generate` 简单模式）存在三类问题：

1. **收藏/归档无反馈** — `toggleCollection` 成功路径没有任何 toast，用户点击后看不到变化。
2. **"收藏只能收藏一个"的错觉** — 前后端排查确认无单选逻辑（`setOpportunityCollectionStatus` 是单行 `UPDATE ... WHERE id=?`，前端是单卡独立 toggle）。真正根因是"无反馈 + 视觉态弱"，用户误以为只生效一个。
3. **字号不符合设计风格** — rank 区标题被压到 9px、ranking-boundary 段落 10px、零星 7/8px，低于全站事实字号下限 11px。根因是 rank 行把 6 个元素塞进一行，为塞下而缩小字号。

## 事实基线（CDP 实测计算字号，非 CSS 行数）

项目有颜色 token（`--ink`/`--line` 等）但**无字号 token**，字号全是硬编码 px，且大量是被 cascade 覆盖的死声明。CDP 抓取选题页计算后字号，真实刻度为：

| 计算字号 | 命中元素数 | 角色 |
|---|---|---|
| 16px | 308 | 基准（按钮/输入继承 root 16px） |
| 13px | 79 | 正文 |
| 12px | 104 | 次要文字 |
| 11px | 89 | 标签/辅助（事实下限） |
| 14px | 23 | 强调 |
| 10px | 40 | ⚠️ 偏小 |
| 9px | 33 | ⚠️ 越界（含选题卡 rank） |
| 7-8px | 33 | ⚠️ 严重越界 |

事实刻度：`11 / 12 / 13 / 14 / 16`（页面 h1 另有 29px）。

## 设计决策（已与用户逐条确认）

1. 字号基准：**以设计系统 token 为准** — 固化事实刻度为 `--font-*` token。
2. 反馈模型：**toast + 卡片视觉态 + 顶部计数**（最完整档）。
3. rank 行：**重排为信息层 + 操作层两层结构**。
4. 归档语义：**归档 = 从默认视图移除**（移出视线，切筛选器才可见）。

## 第 1 节：字号 Token 体系

在 `:root` 新增字号 token，固化事实刻度：

```css
--font-2xs: 11px;   /* 标签/辅助文字（事实下限） */
--font-xs:  12px;   /* 次要正文 */
--font-sm:  13px;   /* 正文 */
--font-md:  14px;   /* 强调 */
--font-lg:  16px;   /* 基准（按钮/输入继承） */
```

选题页越界字号重映射（只动 <11px 的越界项，已合法的不动）：

| 位置 | 现在 | 改为 |
|---|---|---|
| `.opportunity-card__rank strong`（标题） | 9px | `--font-sm` 13px |
| `.opportunity-card__rank small` | 8px | `--font-2xs` 11px |
| `.opportunity-ranking-boundary p` | 10px | `--font-xs` 12px |
| rank 区其余 7/8px 零件 | 7-8px | `--font-2xs` 11px |

边界：只固化已存在刻度、只修选题页 <11px 越界，不全站扫改（避免回归）。

## 第 2 节：收藏/归档反馈

改动集中在 `IntelligentSimpleFlow.tsx` 的 `toggleCollection` 与面板头部。

**① Toast（补成功路径）**

| 操作 | 结果状态 | Toast |
|---|---|---|
| 收藏 | collected | 「已收藏」success |
| 取消收藏 | active | 「已取消收藏」default |
| 归档 | archived | 「已归档」success |
| 取消归档 | active | 「已取消归档」default |

**② 卡片视觉态（持久标记）**

- `collected` → 卡片描边高亮 + 信息层「★ 已收藏」角标
- `archived` → 卡片置灰降透明度 + 「已归档」角标
- 标记放入第 3 节的信息层。

**③ 顶部计数 + 筛选联动**

- 面板头部显示 `已收藏 N · 已归档 M`，N/M 由 `opportunities` 实时派生。
- 点击计数 = 切到对应筛选器（复用 `collectionFilter` state），与下拉筛选器双向同步。

**数据流**：`toggleCollection` 成功 → 更新 `opportunities` state → 计数、视觉态、筛选结果全部由该 state 派生，单一数据源。

## 第 3 节：rank 行重排（信息层 + 操作层）

`.opportunity-card__rank` 从「一行 flex」改为「两行」结构：

```
┌─ 信息层 (.opportunity-card__rank-info) ──────────────┐
│  [标题 strong 13px]  [分数 Badge]  [★已收藏/已归档角标] │
├─ 操作层 (.opportunity-card__rank-actions) ───────────┤
│  [收藏]  [归档]  [编辑度量]  [删除]                     │
└──────────────────────────────────────────────────────┘
```

要点：
- 信息层：标题 `--font-sm`(13px)，角标 `--font-2xs`(11px)；`flex-wrap` 允许角标掉行但标题永远完整。
- 操作层：4 个操作按钮成组，统一尺寸/间距；窄屏 `flex-wrap` 平铺。
- 收藏/归档按钮体现当前态（已收藏时激活样式，再点即取消）。
- 删除按钮保持危险色。

边界：只重排 rank 行 DOM 与对应 CSS，卡片其余部分（正文 `p`、ranking-boundary）不动结构，只随第 1 节调字号。

## 第 4 节：归档语义 + 默认视图过滤

语义：收藏 = 标星珍藏（仍要看）；归档 = 看过收起（移出视线）。

筛选器行为（`collectionFilter` state + `visibleOpportunities`）：

| 筛选值 | 显示内容 |
|---|---|
| 全部（默认） | 未归档的卡片（active + collected），不含 archived |
| 已收藏 | 仅 collected |
| 已归档 | 仅 archived |

关键改动：默认视图从"显示全部"改为"显示未归档"。

边界情况：
- 归档一张卡 → toast「已归档」→ 该卡从当前默认视图移除 → 顶部计数 M+1。
- 在「已归档」视图取消归档 → 卡片回 active → 从归档视图移除。
- 全部归档后默认视图空 → 复用现有空态，文案提示"去已归档查看"。

边界：只改 `visibleOpportunities` 过滤逻辑和默认筛选值，不动数据层。

## 验证策略

- 每节改动后跑 build/typecheck。
- CDP 复测选题页计算字号：确认无 <11px 越界。
- CDP 复测 rank 行：1280 与 1024 窄屏均不炸行、标题完整。
- 浏览器交互验证：收藏/归档/取消 toast 正确、视觉态正确、顶部计数与筛选联动、归档移出默认视图。
