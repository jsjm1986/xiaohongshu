# 极简创作频道 · 完整化(单页多标签)设计文档

## 背景与目标

现有 `/quick`（极简创作）是一个线性向导：建项目 → 传资料 → 挑选题 → 生成。它能跑通主链，但不是一个"自成一体"的频道——用户要做项目管理（改名/删项目、维护知识文件、回看历史产出）仍得切到别的频道。

本次目标：把 `/quick` 升级为**单页多标签的完整频道**，让简单用户在这一个页面内完成一个项目的全生命周期——建/管项目、维护知识、挑选题、配置、生成、回看历史——**不需要切换到任何其他频道**。整体保持简化：默认只露必要项，高级设置收进折叠区。

## 硬约束

- **零后端改动。** 纯前端扩展，所有能力走现有 API 端点。
- **不改动其他频道的业务逻辑与前端。** IntelligentSimpleFlow / GeneratorPage / KnowledgePage / ProjectsPage / simple-generation 等一律不动。
- **现有文件仅授权少量行改动：** `App.tsx`（`/quick` 路由 element 换成新壳 + import）。`AppShell.tsx` 导航项不变（仍是「极简创作」→ `/quick`）。删除旧 `QuickCreatePage.tsx`（已决定直接替换，不保留旧向导）。
- **只显示可用文案。** 结果沿用上一版 `quickCandidateFields` 白名单投影，绝不渲染审计字段（score/diagnostics/sources/validation 明细等）。
- **复用已测资产，禁止重写。** 复用 `autoApproveAndGenerate`、`quickCandidateFields`、`quickCandidateToMarkdown`、`QuickResult`（上一版已测），以及 `resolveSimpleGenerationSettings` / `buildSimpleGenerateInput`。
- **测试遵循现有运行器约束。** web 包 `node --test` 无 jsdom/React 渲染环境，只写纯逻辑测试；新测试文件追加进 `apps/web/package.json` 的 test 脚本列表。

## API 能力核实（真实签名，非猜测）

已核实 `apps/web/src/lib/api.ts` 与 `ProjectContext.tsx`：

- 项目：`useProjects()` 提供 `addProject({name})` / `updateProject(id, Partial<Project>)` / `removeProject(id)` / `refresh()`（全部齐备，支持项目 CRUD）。
- 知识：`api.knowledge.list(projectId)` → `{items, total}`；`upload(projectId, file, category, kind)`；`create(projectId, filename, content, category, kind)`；`remove(id)`。**无 PATCH**——不能就地改分类。
- 分析：`api.intelligence.analyze(projectId, force=false)`（阻塞直至完成）；`api.intelligence.get(projectId)`（有 `approvalStatus`）。
- 选题：`api.opportunities.list(projectId)` → `{items, total}`；`refresh(projectId, userGuidance?)`；`approve(projectId, id)`。
- 依赖审批：`api.blueprintModules.list/approve`、`api.informationGaps.list/approve`、`api.expressionStrategies.list/approve`（`autoApproveAndGenerate` 已封装其顺序）。
- 预设：`api.presets.list(projectId)` → `{items, total}`（`ContentPreset` 有 `isDefault`）。
- 生成：`api.generations.create(input)` / `get(id)` / `list(projectId?)` / `exportUrl(id, candidateId, format)`。**无 DELETE**——历史不能删除。

**两个由 API 限制导出的能力边界（已与用户确认按现状顺应，不加后端）：**
1. **历史无删除**：⑤历史标签只做查看 + 复制 + 导出。
2. **知识无就地改分类**：①知识文件改分类 = 删除后重新上传（选新分类）。

## 标签内容与交互

### ① 项目 & 知识
- **项目选择器**：下拉现有项目 + 「新建」。切换项目会级联清空下游（选题/结果）。
- **新建**：项目名输入 + 建立按钮 → `addProject({name})`。
- **项目管理**：重命名（`updateProject(id,{name})`）、删除（`removeProject(id)`，二次确认）。城市/医生/生成默认值收进「项目设置」折叠区（`updateProject` 透传）。
- **知识文件列表**：`knowledge.list` 展示（名称/分类/证据类型），可删除（`knowledge.remove`）。
- **上传**：.md/.txt 多选。简化——分类默认「未分类」、证据类型默认「已知事实」；「高级」链接展开可逐文件改分类/类型（改分类靠删重传的说明就近提示）。
- **分析**：「分析知识库」→ `intelligence.analyze(id, true)`，完成后点亮②并自动切换。
- 已分析项目重进：显示已有知识文件数，可直接去②。

### ② 选题
- 分析产出的选题卡片列表，**只显示标题**，点选即选中并高亮。
- 「换一批」：可选填引导词（折叠）→ `opportunities.refresh(id, guidance?)`。
- 选中一个 → 点亮③。

### ③ 配置
- **必露**：预设下拉（默认选 `isDefault`）。
- **高级折叠区**（默认收起，全给默认值）：读者阶段、内容入口、评论信息丰富度、城市（datalist 用项目 cities）、医生、必含词、禁用词。不展开也能生成。
- 「生成文案」→ `autoApproveAndGenerate({project, opportunityId, presetId, overrides})`，期间禁用 + 加载态，完成后点亮④并切换。

### ④ 结果
- 现有 `QuickResult`（3 版标签页 + 逐卡复制 + 复制全部）。
- 动作：「再来一批」（重跑生成）、「换个选题」（切回②）。

### ⑤ 历史
- `generations.list(projectId)` 展示本项目历次生成产出（标题/时间/状态）。
- 每条可展开看候选文案、复制、导出（`exportUrl`）。**无删除**（API 限制）。

## `autoApproveAndGenerate` 增量扩展

当前签名 `{project, opportunityId, presetId, pollIntervalMs?, maxPolls?, deps?}`。本次**增量加一个可选 `overrides?: SimpleSettingOverrides` 参数**，透传给 `buildSimpleGenerateInput` 已支持的 `overrides`，用于承载③配置标签的高级设置。这是对已测函数的向后兼容扩展（可选参数，不破坏现有调用），非后端改动。

## 数据流

```
① 建/选项目 → setProject → 解锁上传/分析;换项目级联清空下游
① 上传 + 分析 → analyze(force) → setOpportunities → 点亮②并切换
② 选选题 → setOpportunityId → 点亮③;换选题清空结果
③ 选预设 / 调高级 → setPresetId / setOverrides
③ 生成 → autoApproveAndGenerate({project,opportunityId,presetId,overrides})
        → results = candidates.map(quickCandidateFields) → 点亮④并切换
④ 再来一批 → 重跑生成;换个选题 → 切回②
⑤ 历史 → generations.list(projectId) → 查看/复制/导出
```

## 标签可达性与级联失效（`quick-channel-state.ts` 纯函数）

- `tabReachable(state)` 返回各标签 enabled：①恒亮；②需 `opportunities.length>0`；③需 `opportunityId`；④需 `results.length>0`；⑤需 `project`（有项目即可看历史）。
- 已亮标签自由切换、不丢状态；未亮标签禁用（灰显 + tooltip 说明前置条件）。
- 级联失效（纯函数）：换项目 → 清空 opportunities/opportunityId/results；换选题 → 清空 results。
- 这些逻辑无副作用，是本频道唯一的纯逻辑单测点。

## 错误处理

每个异步动作（建/改/删项目、上传、分析、换一批、生成、删知识、加载历史）独立 try/catch → `toast.push(msg,'error')` + 清 busy + **停在当前标签**（不跳转，让用户重试）。分析/生成失败不点亮下游标签。删除类动作（删项目/删知识）二次确认。

## 范围外（明确不做）

- 公式编辑（FormulasPage）、研究治理（ResearchPage）、审计（AuditPage）等专家重度功能——留在原频道，不搬入本页。
- 账户级设置（模型提供商/API Key/额度，SettingsPage）——全局设置，归 `/settings`。
- 历史删除、知识就地改分类——现有 API 不支持，按边界顺应（不加后端）。
