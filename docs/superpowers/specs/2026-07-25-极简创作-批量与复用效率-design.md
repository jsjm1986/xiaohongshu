# 极简创作 · 批量与复用效率 设计文档

- 日期:2026-07-25
- 频道:极简创作(`/quick`,独立产品壳 QuickShell)
- 目标用户:有经验的内容运营(懂小红书玩法,不懂底层逻辑),核心诉求是**高效**——批量、快捷、历史复用、一眼看懂产出质量
- 本轮范围:**批量与复用效率**。底层生成/合规/分析逻辑零改动,只做产品化的批量能力 + 复用链路打通。

## 背景与定位

`/quick` 已从"频道"升级为独立产品:独立壳 QuickShell(顶栏+居中)、产品首页 QuickHome(项目卡墙)、四区结构(总览/知识库/创作/产出)、SaaS 用户类型(saas 用户锁在 `/quick`+`/settings`)。

本轮把它推向"真正成熟、面向独立用户组"的产品。针对"内容运营要量"的现实,补齐三件事:**二维批量生成**(多选题 × 多预设)、**跨会话持久的批次看板**、**历史配方回填**,并顺带打通预设/模板的复用体验。

## 技术前提(已核实)

- 后端**已是异步 job 模型**:`POST /api/generations` 返回 job(带 `status: queued/running/completed/failed`、`progress`),前端 `GET /api/generations/:id` 轮询。现在的 `autoApproveAndGenerate` 只是把它包装成同步等待。
- `generation_jobs` 表已有:`project_id / status / progress / opportunity_id / preset_id / created_by / created_at`,以及快照列 `opportunity_snapshot_json / config_impact_json / image_context_json / resolution_snapshot_json`。
- 最新迁移版本 **user_version = 11**,本轮批次迁移为 **v12**。
- 有 `generation_events` 事件表可复用。

**结论**:批次落地不用重写生成核心,只需加"批次账本 + 展开接口";配方回填是纯前端读快照回灌。

## 架构方案:后端批次实体 + 服务端展开(方案 A)

前端提交批量时,把"选中的 N 个选题 × M 个预设 + 公共 overrides + 图片"整包发给后端新接口,**后端一次性把所有子 job 建好入队**,返回批次 + job 列表。前端拿批次 id 进看板轮询、实时翻牌。

选此方案的理由:唯一真正兑现"跨会话持久"的形态——提交那一刻所有 job 已落库入队,哪怕立刻关页面/换设备,回来看进度和结果都在。轻量分组(前端循环建 job)在"逐个建 job"中途关页面会丢任务,不达标;时间窗聚合不持久,直接排除。

## 第 1 节:批次数据模型(后端,迁移 v12)

### ① 新建 `generation_batches` 表

```sql
CREATE TABLE generation_batches (
  id           TEXT PRIMARY KEY,
  project_id   TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  name         TEXT NOT NULL DEFAULT '',      -- 批次名(默认按时间/选题数自动生成,可留空)
  status       TEXT NOT NULL,                 -- queued / running / completed / failed / partial
  total_jobs   INTEGER NOT NULL DEFAULT 0,    -- 子任务总数(冗余存,免每次 count)
  config_json  TEXT NOT NULL DEFAULT '{}',    -- 批次级配置快照:选题ids × 预设ids、公共 overrides、图片
  created_by   TEXT NOT NULL REFERENCES users(id),
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL,
  completed_at TEXT
);
CREATE INDEX generation_batches_project_idx ON generation_batches(project_id, created_at);
```

### ② `generation_jobs` 加一列

```sql
ALTER TABLE generation_jobs ADD COLUMN batch_id TEXT REFERENCES generation_batches(id) ON DELETE SET NULL;
CREATE INDEX generation_jobs_batch_idx ON generation_jobs(batch_id);
```

`ON DELETE SET NULL`:删批次不连带删 job(产出仍留历史区,只脱离批次),契合"产出不丢"。单篇生成 job 依旧 `batch_id = NULL`,与现有逻辑零冲突。

### 批次状态聚合规则(后端按子 job 算)

- 任一 job 在 `queued/running` → 批次 `running`
- 全部 `completed` → 批次 `completed`
- 全部 `failed` → 批次 `failed`
- 有成功有失败、无进行中 → `partial`(运营挑成功的用、单独重试失败的)

### 关键取舍

批次表**不存产出内容**——产出仍在各 job 的 `content_packages`。批次只是"一组 job 的账本 + 配置快照"。既不重复存储,又让"批次删了产出还在"自然成立。

## 第 2 节:批次看板 UI

### 位置

第四区"产出"(HistoryTab)升级为**产出中心**,不新增导航项。分两层:
- **进行中/最近批次**(新增):卡片墙,每批次一张大卡,进行中的置顶,跑完沉入下方
- **单篇产出历史**(现有):保留现在的列表(带筛选/搜索)

### 批次大卡(展开态,卡片墙)

```
┌─ 批次:美白系列 5 选题 ×2 版本         [running 6/10] ─┐
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐  ...           │
│  │选题A·口语│ │选题A·专业│ │选题B·口语│ │选题B·专业│              │
│  │ ✓ 可发布│ │ ⟳ 45%  │ │ ✓ 待核查│ │ ⋯ 排队 │              │
│  └────┘ └────┘ └────┘ └────┘                │
│  [挑选可发布的] [全部导出]              失败 2 [重试] │
└──────────────────────────────────────────┘
```

### 子卡三态翻牌(一个"选题×预设" job)

- **排队/生成中**:进度%(复用现有 `progress` 轮询)
- **完成**:选题名 + 预设名 + **一眼质量标**(可发布/待核查——复用现有 `publishable` 与 issueCodes 一句话结论),点击展开看全文(复用现有候选卡)
- **失败**:错因 + 单独 [重试](只重跑这一个 job)

### 实时填充

进看板时,对批次内所有 `queued/running` 的 job **并发轮询** `GET /api/generations/:id`(复用现有轮询,从"一个"变"多个"),谁先完成谁先翻牌;全部终态后停止。

### 批次级操作

- **挑选可发布的**:一键筛出所有 `publishable` 产出
- **全部导出**:批量导出(复用现有 export)
- **失败重试**:对 failed 的 job 批量或单个重试

### 关键取舍

看板**不是新页面**,是产出区上半部分。运营提交批量后落到这里,边等边看已完成的,跑完在同一处挑内容、导出。

## 第 3 节:批量提交入口

把创作区从"单篇"升级到"二维批量",且不破坏顺手的单篇流程。

### 左栏(选题池)加多选

- 每个选题卡左侧加**勾选框**(默认不勾)
- 不勾任何选题 = 现在行为(点选题名 = 选中单个,右栏配单篇)
- 勾选 ≥1 个 → 左栏底部浮出**批量操作条**:`已选 3 个选题 [配置批量生成]`
- 单选(点名字)与多选(勾选框)并存不打架:随手点是单篇,勾几个是批量

### 右栏配置区:单篇/批量两态

- **单篇态**(点选题):现在的 ConfigTab,一个预设 + 高级设置 + 生成文案
- **批量态**(点"配置批量生成"):

```
批量生成 · 3 个选题
├ 选版本(预设多选):□口语化 ☑专业向 ☑种草向  → 3 选题 × 2 预设 = 6 篇
├ 公共高级设置(可留空,应用到所有):读者阶段/入口/城市/医生…
├ 源素材图(可选,应用到所有)
└ [提交批量生成 · 共 6 篇]   ← 一眼看到总量
```

### 提交动作

点"提交批量生成"→ 调 `POST /api/generation-batches`(选题ids × 预设ids + 公共 overrides + 图片)→ 后端展开成 N 个 job 入队 → 前端跳产出区看板,开始实时填充。

### 总量护栏

实时算 `选题数 × 预设数`,超过阈值(如 20 篇)给提示确认(避免误点几十篇),但不硬禁止。

### 关键取舍

1. **不新建"批量模式"开关**——靠勾选框有没有勾自然区分单/批量,零学习成本
2. **预设卡片化一箭双雕**:批量"多版本选择" + "预设卡片保留"
3. 单篇流程**完全不变**

## 第 4 节:历史配方回填("再来一篇同款")

### 配方包含(从 job 快照还原)

- 选题(`opportunity_id` / `opportunity_snapshot`)
- 预设(`preset_id`)
- 高级参数(`config_json` overrides:读者阶段/入口/评论丰富度/城市/医生/必含词/禁用词)
- 源素材图(`image_context`,可选带上)

这些生成时已快照进 `generation_jobs`,回填是**纯前端读快照 + 状态回灌**,不动后端。

### 入口

产出区每篇产出(单篇历史卡、批次子卡)加操作 **[再来一篇]**:
- 点击 → 读该 job 配方 → 回灌创作区状态(`opportunityId / presetId / overrides / imageAssetIds`)→ 跳创作区
- 落地即"可生成"态,可直接生成或微调后再生成

### 边界处理(诚实面对快照失效)

- **选题还在选题池** → 正常选中
- **选题已删/归档** → 提示"原选题已不在选题池",仍回填预设+参数,让运营挑新选题套用(配方价值主要在预设+参数)
- **预设已删** → 回落默认预设,提示"原预设已删除,已用默认"

### 关键取舍

回填**只回灌创作区、不自动生成**——留微调机会,避免手滑重跑一模一样的。落地是"准备好等你按生成",不是"已经在跑"。与现有"存为预设"配合覆盖"同款"全部诉求,不引入新抽象。

## 第 5 节:预设卡片化 + 模板打通

### ① 预设卡片化(ConfigTab)—— 替换现在的 `<select>` 下拉

单篇态与批量态共用同款卡片,差别只在单选/多选:

```
内容预设(单篇:单选 / 批量:多选)
┌─────┐ ┌─────┐ ┌─────┐
│口语化短帖 ★默认│ │专业科普向    │ │种草安利向    │
│轻松口语、真实感 │ │严谨、多依据   │ │强种草、促转化 │
└─────┘ └─────┘ └─────┘
[+ 存为预设]
```

- 每张卡:预设名 + 一句简述(description)+ 默认标 ★
- 单篇态:点选一张(单选),选中高亮
- 批量态:勾多张(多选),右上打勾
- 卡片操作(设默认/删除)收到卡片 hover 或卡内小图标,不再是下方一排按钮
- "存为预设":末尾虚线"+"卡,或卡片区下方入口

### ② 引导词模板打通(TopicTab 的"换一批")

现状已不错(模板 chips 一键填入),小幅优化:
- 引导词模板 chips **保留一键填入**
- "存为模板"入口更顺手(减一层弹窗,内联命名)
- 这块改动最小,已基本达标

### ③ 为什么不合并两者(明确边界)

- **预设** = 文案怎么写(风格/结构),作用在 ConfigTab
- **引导词模板** = 换一批选题的方向,作用在 TopicTab
- 合并成"创作方案"会引入新数据模型,和"批次"叠加撑爆范围。故只打通复用体验,不动数据模型。

### 关键取舍

预设卡片化是本轮唯一"纯 UI 但影响面较大"的改动(替换核心选择控件),同时服务"预设卡片保留"与"批量多版本选择",一箭双雕。

## 范围总览

| 节 | 改动 | 后端 |
|---|---|---|
| 1 批次模型 | `generation_batches` 表 + `batch_id` 列(v12) | ✅ 动 |
| 2 批次看板 | 产出区上半部,卡片墙实时填充 | 读 |
| 3 批量提交 | 选题多选 + 预设多选 → 批量提交接口 | ✅ 动(展开接口) |
| 4 配方回填 | 产出"再来一篇"→ 回灌创作区 | 纯前端 |
| 5 预设卡片化 | 下拉→卡片(单选/多选) | 纯前端 |

后端集中在第 1、3 节(批次表 + 展开接口),其余前端。底层生成/合规/分析逻辑**零改动**。

## 非目标(本轮不做)

- 会话级临时看板(已选跨会话持久)
- "创作方案"统一抽象(预设与模板保持各归其位)
- 批次的定时/周期调度、跨项目批量
- 产出到小红书的直接发布集成

## 测试策略

- **后端**:批次迁移 v12 幂等性;`POST /api/generation-batches` 展开 N 个 job 正确、batch_id 关联正确;批次状态聚合(running/completed/failed/partial)单测;删批次 job 保留(SET NULL)。
- **前端**:批量提交入口的选题多选 × 预设多选组合计数;看板并发轮询与三态翻牌;配方回填的三种边界(选题在/删/归档、预设删);预设卡片单选/多选切换。
- **验证**:web typecheck/build 0 error;现有测试保持全绿;浏览器实测批量提交→看板填充→挑可发布→配方回填闭环。
