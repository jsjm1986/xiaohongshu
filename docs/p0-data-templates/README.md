# 星零感微孔去眼袋 · P0 数据模板包（复核清单版）

> **2026-07-23 修订**：本包已从"手工填表方案"改为"AI 分析 + 人工复核清单"。
> 原因：系统的原生设计就是**上传知识库 → AI 分析自动抽取**（蓝图/缺口/答案/证据），此前缺口答案为空是因为分析模型拿不到可引用的证据句柄。该问题已在代码侧修复——分析源现在为每篇知识文件携带节级 `evidenceSections`（与生成时接受的证据引用逐位一致），Stage 2 提示词已强制"知识能答的缺口必须填答案+边界+证据ID"。
> **你不需要手工填表，也不用手动拆分知识库——单个 `眼袋王.md` 即可。**

## 正确流程（四步）

### ①（可选，一分钟）修复知识文件 frontmatter

旧 `眼袋王.md` 的 frontmatter 起始行损坏（首字节缺 `---`），系统目前靠路径推断兜底（kind=fact），能正常工作。如需显式声明，把文件开头改成：

```
---
kind: fact
evidenceStatus: user_supplied
title: 星零感微孔去眼袋 AI 知识库
source_file: 星零感微孔去眼袋项目资料卡_AI理解版(1).docx
---
```

重新上传（会自动成为新版本）。不修复也不影响后续步骤。

### ② 点「分析项目」

在项目页/生成页点一次分析。新版分析会：

- **蓝图**：role_model 产出 ≥6 个提问侧角色 + 恰好 1 个可追责答复身份（发布账号/楼主）——对照 `role-model.md` 检查；
- **缺口池**：知识库能答的缺口应自动带上 answer + boundary + evidenceIds（节级证据）——对照 `gap-answers.md` 逐个复核。

### ③ 逐项复核并批准（人工门禁，不可省）

- 缺口池：对照 `gap-answers.md`，AI 填的答案与知识库口径（§5.1 价格、§6.2 恢复、§7 医生/地址、§9 FAQ）一致→批准；不一致→点开编辑器修改（答案可改、证据可用点选器换）后批准。**AI 没填的缺口属正常**——那是知识库确实没口径的（专利、正式条款、执业资质、案例量等），保持 unknown。
- 蓝图 7 个模块：重点看 role_model（对照 `role-model.md`）与 scenario_model 的 prohibitedUnsupportedHistories（对照 `scenario-prohibited-histories.md`），确认后批准。
- 选题卡照常确认。

> ⚠️ **顺序红线：填完/改完答案后，不要再点「分析项目」。** 重新分析会插入一整套全新 id 的缺口（旧缺口留在池里但不再被引用），你的复核成果会变孤儿、缺口池还会翻倍。要改就用缺口编辑器单点修改。

### ④ 重新生成

生成后重点抽查：评论区答复是否挂在"发布账号（楼主）"身份下、答案是否来自缺口池口径、动态信息是否带"以当期确认为准"、台账是否对这些答案记了 fact（导出/结果页可见证据引用）。

## 文件清单（现为复核标准，不再是填报模板）

- `gap-answers.md` — 复核清单：8 个知识库可答缺口"应该有的答案与边界" + 7 个应保持 unknown 的缺口清单
- `role-model.md` — 复核标准：分析产出的 role_model 应该长什么样（1 答复者+7 提问者）；分析结果明显不达标时可手工整体替换为其中 JSON
- `scenario-prohibited-histories.md` — 复核标准：三个 family 的 prohibitedUnsupportedHistories 应为动作类条目
- ~~`knowledge/`（4 个拆分文件）~~ — **已废弃**：单文件 + AI 分析路径下不需要手工拆分；如未来要做机器级状态隔离可参考，但正常情况下用不到

## 如果 AI 分析没填答案（兜底）

供应商模型不稳定或输出不合规时，分析可能仍留空答案。此时才退回手工：按 `gap-answers.md` 在缺口编辑器填入 answer/boundary 并用点选器挂证据。手工编辑与 AI 填写在系统里完全等价（都走 draft→approve）。
