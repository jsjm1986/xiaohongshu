# 星零感微孔去眼袋 · P0 数据模板包

本目录是给“星零感微孔去眼袋”项目补数据用的模板包，配合评论区（Cref）v1.1 契约（publisher 答复身份、节级证据、缺口答案驱动、角色谱要求）使用。所有内容通过 UI 填入，不直接改库。

**注意：这是一次业务口径确认动作。** 模板中的价格、医生资质、保障条款、地址等内容均标有动态或待核验状态，请机构确认无误后再点批准。任何一次编辑保存都会让对应模块回到 draft，必须重新批准才会进入后续生成。

> ⚠️ **顺序红线：填完缺口答案后，不要再点「分析项目」。** 重新分析会插入一整套全新 id 的缺口（旧缺口留在池里但不再被新选题卡引用），你填好的答案会变成孤儿、缺口池还会翻倍。role_model 的修正请走步骤③的 JSON 编辑器整体替换（不要靠重新分析生成）。如果你坚持要重新分析生成蓝图/缺口，顺序必须反过来：**先分析 → 后填答案**。

## 文件清单

- `knowledge/可对外口径.md` — 知识库：可对外事实（kind: fact）
- `knowledge/动态信息_以当期为准.md` — 知识库：价格／恢复／地址等动态信息（kind: fact，带 caveats）
- `knowledge/待核验.md` — 知识库：待核验信息（kind: unknown）
- `knowledge/禁止承诺.md` — 知识库：禁止承诺与改写表（kind: prohibited）
- `gap-answers.md` — 缺口池：8 个缺口的答案模板＋7 个保持 unknown 的缺口清单
- `role-model.md` — 蓝图 role_model 修正版完整 JSON（1 答复者＋7 提问角色）
- `scenario-prohibited-histories.md` — 蓝图 scenario_model 三个 family 的 prohibitedUnsupportedHistories 修正

## 操作步骤

### ① 知识库页面：上传 4 个新文件，删除旧文件

1. 在知识库页面逐一上传 `knowledge/` 下的 4 个 .md 文件。
2. 删除旧的“眼袋王.md”（原资料卡）。旧文件 frontmatter 已损坏——首字节缺 `---` 起始行，系统要求 frontmatter 以 `---\n` 开头才会解析 kind／evidenceStatus 等元数据，旧文件实际是在无元数据状态下入库的；4 个新文件已带合规 frontmatter。
3. 上传后确认各文件识别出的 kind：可对外口径＝fact、动态信息＝fact、待核验＝unknown、禁止承诺＝prohibited。

### ② 缺口池：填 8 个答案，7 个保持 unknown

1. 打开 `gap-answers.md`，按其中的 title 在缺口池编辑器中逐个找到缺口。
2. 对第一部分列出的 8 个缺口，填入 answer 与 boundary，并用编辑器里的**证据点选器**（按文档分组的知识分节列表，带摘要，勾选即可，不用手输 ID）关联 evidenceNote 指明的分节。如果某个已保存的引用变成黄色的"失效引用"（通常是知识文件被替换导致），必须显式移除后才能保存——系统不会替你静默丢弃。
3. 第二部分列出的 7 个缺口（完整禁忌证、详细对比参数、专利状态、满意后付款条件、术后异常处理、真实案例、联合治疗）知识库没有现成口径，**保持 unknown，不填**。

### ③ 蓝图 role_model：JSON 编辑器整体替换

1. 蓝图页打开 role_model 模块的 JSON 编辑器。
2. 用 `role-model.md` 中代码块的完整 JSON 整体替换现有内容（要点：素人口吻 hostVoiceTraits、1 个可追责的“发布账号（楼主）”答复者、7 个提问侧角色、答复身份统一为发布账号）。
3. 保存（模块回 draft）后重新批准。

### ④ 蓝图 scenario_model：补 prohibitedUnsupportedHistories

1. 按 `scenario-prohibited-histories.md` 的对照表修改三个 family 的 `prohibitedUnsupportedHistories` 字段，其余字段不动。
2. 保存（模块回 draft）后重新批准。

### ⑤ 重新生成

全部涉及模块重新批准后，再重新生成内容包。生成后重点抽查：评论区答复是否挂在“发布账号（楼主）”身份下、答案是否来自缺口池已填口径、动态信息是否带“以当期为准”提示。
