# 研究与证据中心

研究与证据中心用于长期管理方法论依据、实验和参数版本。它不会把“有引用”误当成“已证明”，也不会让尚未复核的研究记录悄悄改变生成结果。

## 记录对象

- **理论主张**：分别登记项目定义、外部研究、内部观察、推理、猜想和信息不足。相同主张的修改应建立新版本。
- **论文与来源**：引用、链接、“实际支持什么”和“不支持什么”必须分开填写；主张与来源通过支持、反驳、限制或背景关系连接。
- **实践数据**：每个数据快照保存 SHA-256、记录数、存储位置、采集来源和样本局限。文件变化后必须建立新快照。
- **实验**：按 `draft → preregistered → running → completed → replicated` 推进。开始运行前不能登记结果；结果需单独复核。
- **参数校准**：记录当前值、建议值、理由、证据和风险。只有注册过的生成参数能够进入运行时发布。
- **发布清单**：冻结应用、公式、执行策略、提示合同、参数策略和证据目录的版本与摘要，并绑定批准的数据、实验结果和校准提案。

## 运行时边界

研究文本和论文不会自动注入生成提示词，实验完成也不会自动调整参数。校准只有完成以下链路才生效：

```text
创建提案 → 审核批准 → 绑定新发布清单 → 批准清单 → 激活清单
```

激活时服务端再次验证公式与各运行合同摘要；版本过期、数据未批准或结果未批准都会拒绝激活。每个生成任务冻结 `releaseManifestId` 和完整研究版本快照。发布清单给出的参数是项目默认覆盖，用户本次生成明确填写的值仍优先。

## 初始资料与更新

新项目会导入 `docs/audit/formula-evidence-catalog.json` 的公式审计记录，并把 `../70篇对标内容_AI提炼版.jsonl` 冻结为内部描述性样本。该样本不是随机抽样，不能证明平台推荐机制、转化因果、最佳参数阈值或总体用户分布。

后续真实实验或线上观察应建立新的数据快照和实验版本，不要修改旧记录。通过新的发布清单激活校准，即可把“当时为什么这样生成”与后续版本完整对比。

## 权限与审计

查看、编辑、审批和发布采用独立权限。创建、复核、状态推进与激活都会写入工作区审计日志。建议由不同成员承担记录与审批；生产发布前至少复核来源边界、数据指纹、实验状态和校准影响。
